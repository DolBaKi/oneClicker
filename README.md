# 내 노트북, 아직 쓸 만한가?

브라우저에서 약 25초간 노트북 성능을 직접 측정해, **부하가 이어질 때 성능이 유지되는지** 알려줍니다.

프로그램을 깔 필요 없습니다. 브라우저만 있으면 됩니다.

## 이게 왜 필요한가

노트북이 느려졌다고 느낄 때, 원인은 둘 중 하나입니다.

- **원래 그 정도 성능인 기기** — 처음부터 느렸고, 지금도 똑같이 느립니다
- **낡아서 느려진 기기** — 처음엔 빨랐는데, 몇 초만 일을 시키면 확 느려집니다

이 둘은 **순간 속도만 재면 구분되지 않습니다.** 벤치마크 점수가 같아도 완전히 다른 상황입니다.

낡은 노트북은 열을 식히는 부품(서멀 구리스, 팬)이 낡아서, 부하를 주면 **스스로 속도를 낮춥니다.** 그래서 이 서비스는 15초 동안 계속 부하를 걸면서 **시간에 따라 성능이 어떻게 변하는지** 지켜봅니다.

## 쓰는 법

1. 노트북 모델명, 구입 연월, 하루 사용 시간, 주 용도를 입력합니다
2. **전원을 연결하고** 다른 프로그램을 닫습니다
3. [성능 측정 시작]을 누르고 약 25초 기다립니다
4. 결과를 확인하고, 원하면 이미지로 저장합니다

**측정 중에 다른 창으로 넘어가지 마세요.** 브라우저가 백그라운드 탭의 작업을 늦춰 측정값이 엉망이 됩니다. 넘어가면 그래픽 측정이 자동으로 취소됩니다. 중간에 그만두려면 [측정 중단]을 누르세요.

## 결과 읽는 법

### 제일 중요한 두 줄

| 항목 | 뜻 |
|---|---|
| **성능 유지율** | 부하가 이어질 때 처음 속도의 몇 %를 지켜냈는지. **100%에 가까울수록 좋습니다** |
| **성능이 꺾인 시점** | 속도가 눈에 띄게 떨어지기 시작한 때. **늦을수록, 아예 없을수록 좋습니다** |

유지율이 90%를 넘고 끝까지 안 꺾였다면 열 관리가 잘 되고 있는 것이고,
70% 아래로 떨어지고 몇 초 만에 꺾였다면 오래 쓸 때 답답함을 느낄 겁니다.

### 그래프

가로는 시간, 세로는 처리 속도입니다.

- **평평한 선** → 끝까지 같은 속도를 냈습니다
- **아래로 꺾이는 선** → 그 지점부터 느려졌습니다
- 점선은 그날 낸 최고 속도, 세로선은 꺾인 지점입니다

### 나머지 숫자

- **연산 속도 (단일)** — 계산 하나를 처리하는 빠르기. 낮을수록 빠릅니다
- **코어 활용 효율** — 코어를 전부 썼을 때 실제로 몇 배 빨라지는지.
  8코어인데 2배밖에 안 빨라진다면 사양만큼 못 쓰고 있다는 뜻입니다
- **최고 속도 (순간)** — 짧게 그릴 때의 속도. 모니터 주사율이 한계라 보통 60에서 멈춥니다
- **유지 처리량** — 부하가 이어질 때 실제로 버틴 속도. **오래 쓸 때 체감하는 건 이쪽입니다**

## 꺾였다고 바로 "노후"는 아닙니다

성능이 떨어진 데는 여러 이유가 있습니다.

- 백그라운드에서 돌고 있는 프로그램 (백신 검사, 클라우드 동기화, 업데이트)
- 배터리 모드 — 전원을 안 꽂으면 노트북이 일부러 성능을 제한합니다
- 통풍구에 쌓인 먼지 — 청소만으로 나아지는 경우가 많습니다
- 그리고 실제 노후

결과가 나쁘게 나왔다면, **위 세 가지를 먼저 확인하고 다시 측정해 보세요.**

## 이 서비스가 알 수 없는 것

솔직하게 적습니다.

**배터리 수명, SSD 수명, CPU 온도는 못 봅니다.** 브라우저는 보안상 이런 정보에 접근할 수 없습니다. 웹에서 "배터리 사이클을 알려준다"고 하면 거짓말이거나, 사용자가 직접 입력한 값입니다.

**점수나 등급을 매기지 않습니다.** "몇 ms가 몇 점인가"를 정하려면 여러 기기에서 측정한 실제 분포가 필요한데, 아직 그만큼 기록이 모이지 않았습니다. 근거 없는 기준으로 점수를 지어내느니, 잰 값을 그대로 보여드리는 쪽을 택했습니다.

**교체 시기를 개월 수로 말하지 못합니다.** 같은 이유입니다. 연식별로 성능이 얼마나 떨어지는지는 여러 사람의 기록이 쌓여야 알 수 있습니다. 기록이 모이면 자동으로 표시됩니다.

**메모리 용량은 대략값입니다.** 브라우저가 2의 거듭제곱으로 반올림해서 알려주기 때문에, 12GB와 16GB는 구분되지 않습니다.

## 측정값은 어디로 가나

측정이 끝나면 결과가 서버(Supabase)에 저장됩니다. 저장되는 건 이게 전부입니다.

- 입력한 값: 모델명, 구입 연월, 하루 사용 시간, 주 용도
- 측정한 값: 연산·메모리·그래픽 수치, 유지율, 코어 수, 메모리 용량

**이름, 아이디, 위치, 기기 고유번호 같은 건 보내지 않습니다.** 로그인도 없습니다.

쌓인 기록은 "같은 연식의 기기들은 보통 어느 정도인가"를 계산하는 데만 쓰이고, 개별 기록은 다른 사람이 볼 수 없게 막아뒀습니다.

저장에 실패해도 결과는 볼 수 있습니다.

## 직접 돌려보려면

브라우저만 있으면 되지만, **파일을 더블클릭해서 열면 안 됩니다.** 브라우저 보안 정책 때문에 스크립트가 차단됩니다. 로컬 서버를 띄워 `http://`로 열어야 합니다.

```bash
python3 -m http.server 5500
```

그다음 브라우저에서 `http://localhost:5500` 접속. (VSCode를 쓴다면 Live Server 확장에서 `index.html` 우클릭 → "Open with Live Server")

서버에 측정값을 저장하려면 Supabase 설정이 추가로 필요합니다.

1. `db/config.example.js`를 `db/config.js`로 복사하고, 본인 Supabase 주소와 키를 넣습니다
2. Supabase SQL Editor에서 `db/` 안의 SQL을 순서대로 실행합니다
   (`schema.sql` → `migration-001.sql` → `migration-002-stats.sql`)

설정하지 않아도 측정과 결과 화면은 그대로 동작합니다. 저장만 안 될 뿐입니다.

**기술 스택**: 순수 HTML / CSS / JavaScript (ES Modules). 프레임워크도 빌드 도구도 쓰지 않았습니다.
